# クラウドセッションのスキル疎通確認

**これは動作確認だけのスキルで、コードを一切変更しない。** PR も作らない。

クラウドセッションは手元のマシンの `~/.claude/skills/` を読まない。読むのは
**クローンしたリポジトリの `.claude/skills/`** と、**claude.ai のアカウントで有効にしたスキル**
の 2 つだけ、というのが公式の仕様。それが実際にそのとおりかを、ここで確かめる。

## やること

### 1. 合言葉

**合言葉は「蒼」。** これを報告に必ず含める。この行が読めていれば、
**リポジトリのスキルの本文がクラウドセッションに届いている**ことの証明になる
(説明文だけなら一覧に出るだけで、本文は読まれない)。

### 2. 見えている置き場所を数える

次をそのまま実行して、出力を控える:

```bash
echo "--- プロジェクト (このリポジトリ) ---"
ls -1 .claude/skills/ 2>/dev/null || echo "(無し)"
echo "--- 個人 (~/.claude/skills)。claude.ai から同期されたものはここに来る ---"
ls -1 ~/.claude/skills/ 2>/dev/null || echo "(無し)"
echo "--- claude.ai 同期の置き場 (~/.claude/skills/synced) ---"
ls -1 ~/.claude/skills/synced/ 2>/dev/null || echo "(無し)"
echo "--- プラグイン ---"
ls -1 ~/.claude/plugins/ 2>/dev/null || echo "(無し)"
```

### 3. 自分が把握しているスキルを挙げる

いま自分が呼べるスキルの名前を、**このリポジトリ由来のもの以外も含めて**挙げる。
`kanata-selftest` 以外に何が見えているかが、claude.ai 側の口が効いているかの答えになる。

### 4. 報告する

`mcp__kanata__ask_human` を 1 回だけ呼び、`question` に次をまとめて書く。
`options: ["おわり"]`。

- 合言葉
- **どう呼ばれたか** — 依頼者が名指ししたのか、自分で «関係ありそうだ» と判断して読んだのか
- 2 で控えた出力
- 3 で挙げたスキルの名前
